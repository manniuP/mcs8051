# 17 - 后端 IR 提示 + 中间层优化（mcs_ir）

> 思路：**编译器只管输出「类 IR 提示」注释，值级优化交给中间层 `tools/mcs_ir.py`**
> （asm 文本级）。好处：优化迭代快，不必每次重编自举编译器。

## 提示格式

后端 `CodeGen.emitTrace` 在每条 AIR 指令前输出一行注释：

```
; v<inst> <tag> <操作数…> [-> @spx<disp>]
```

例：

```
; v2 add_wrap v0 c -> @spx-1
        add a,#0x03
        mov @spx-0x1,a
```

- `v<inst>`：AIR 指令号（值号）；操作数里的 `vK` 是值、`c` 是编译期常量。
- `-> @spx<disp>`：该值的结果帧槽（十进制位移）。
- 注释不影响 `sdas`；中间层消费后删掉。

## 中间层 `tools/mcs_ir.py`（夹在 `mcs_opt.py` 之后、`sdas` 之前）

1. **死 store 消除**：`mov @spx<d>,X` 若 `@spx<d>` 在**整个函数内、除这条 store 之外**
   不再出现（读/写都算出现），说明该帧槽是死值 → 删掉这条 store。
   **计算本身保留**：`mcs_opt` 已把值留在 A，供后续指令直接用。
2. 删掉所有 IR 提示注释。

安全（**必须扫全函数，不能只看 store 之后**）：循环回边会让“store 之后的读”落在
**地址更小**处（循环头读、循环尾写），只看后面会误删循环变量、程序直接跑飞。
函数边界按全局标号 `_sym:` 划分；扫描时跳过注释行（避免提示里的 `@spx<d>` 自证）；
自测含回边用例 `python tools/mcs_ir.py --self-test`。

## 与 `mcs_opt.py` 的关系

`mcs_opt.py` 需把整行注释**附到上一条**（`_parse` 里 `entries[-1].raw += line`），
否则注释会变成新条目、**打断 R1/R3/R4/R5 的跨指令模式匹配**（相邻两条 `mov` 之间会被注释隔开）。

## 实测

`examples/vscode_mixed_xmake_zig` 的 `lib.zig`：主体指令 `mcs_opt` 后 ~7 → `mcs_ir` 后 **5**
（`mov a,dpl; add a,#3; xrl a,#0x2a; mov dpl,a` + 帧）；QEMU 仍 `zig_calc(5)=22`。

主工程各例 CSEG（接 `mcs_ir` 前 → 后）：

| 示例 | 前 | 后 |
| --- | --- | --- |
| `zigns` | 638 | **577** |
| `zigmem` | 1273 | **1217** |
| `zigslice` | 3112 | **2921** |
| `ziglog` | 10381 | **9883** |
| `zigbuzz` | 11356 | **10968** |

QEMU 复核：`zigmem`（`a1 ok…`）、`zigslice`（`102030 … sum=9c`）、`zigns`（`020c`）均正确。

> **坑（必记）**：早期版本只扫 store **之后** → 漏掉**循环回边**（循环尾 store、循环头 read 在
> 地址更小处），误删循环变量 store，`zigmem` 直接不输出。现扫**全函数**：除该 store 外全函数内
> 无任何 `@spx<d>` 出现才删；`--self-test` 含回边用例。
