# 27 上游迁移协定（方便跟上 Zig 1.0）

> 配套：**迁移方案/runbook 见 [`26-上游跟进方案.md`](26-上游跟进方案.md)**。本页是**硬约定**：
> 对 fork（开发树 = `mcs251/compiler`，即 `manniuP/zig-mcs51-backend`）的**每一次改动**都要遵守，
> 目的是让 delta 最小、可 rebase，上游 1.0 来了能尽快跟上。自检：`mcs251/tools/compiler_sync_check.ps1`。

## 0. 一句话

**我们的代码只放约定目录；上游文件只做登记过的最小接入；其余一律不碰。**

## 1. 目录归属（改代码前先看）

| 类别 | 路径 | 规则 |
| --- | --- | --- |
| **私域**（随便改） | `src/codegen/mcs/**` | 后端主体（CodeGen/Mir/encode/forms/abi/device） |
| **私域** | `src/link/Asx.zig` | ASxxxx 输出/链接驱动（放上游 `src/link/` 是目录约定） |
| **私域** | `lib/std/Target/mcs51.zig`、`mcs251.zig` | 目标定义（新增文件） |
| **接入点**（只加最小插桩） | `src/codegen.zig`、`src/target.zig`、`src/Zcu.zig`、`src/Sema.zig`、`src/Type.zig`、`src/dev.zig`、`src/link.zig`、`src/codegen/llvm.zig`、`src/codegen/spirv/Module.zig`、`lib/std/Target.zig`、`lib/std/builtin.zig` | 见 §2，改动须登记到 `26 §1-B` |
| **仓级**（与编译器无关） | `experimental/**`、`README*`、`doc/*.zh.md`、`.github/workflows/**`、`build.zig` | 快照/文档/CI；不掺进接入 commit |
| **上游禁区** | 其余所有 `src/**`、`lib/std/**` | **未登记不得改** |

## 2. 接入点只做最小插桩

- 只在既有 switch/enum/白名单里加**一行/一段**：`.stage2_mcs => …`、`zigBackend` 映射、地址空间、
  调用约定等；不改上游既有逻辑。
- **每次新增接入都要同步登记**到 `26-上游跟进方案.md §1-B` 的表（文件 / 意图）。
- 上游新增 exhaustive switch（新后端/新地址空间/新调用约定）导致编译报错时，按报错补
  `unreachable`/`=> {}` 占位——这是**唯一**允许的「顺手改上游」。
- 与 MCS 无关的上游 bugfix（如 `codegen.zig` 的 `undefPtrBits`）单独 commit，将来可直接上游化。

## 3. commit 分层（rebase 只冲突一小块）

一次提交只做一类，**禁止混合**：

1. `feat(mcs): …` —— 私域新增/修改（`codegen/mcs/**`、`Asx.zig`、`lib/std/Target/mcs*.zig`）。
2. `mcs: integrate …` —— 接入点 patch（**单独一个 commit**，rebase 时只需解它）。
3. `docs|ci|chore: …` —— 仓级（`experimental/`、README、CI）。

> 现状：`40b3dad246` 把 1+2 混在了一起；后续新工作按上述拆。历史不重写。

## 4. 生成物

- `src/codegen/mcs/forms.zig` 由 `tools/gen_mcs_forms.py` 生成，**勿手改**；改指令集只改生成器/TSV 后重生成。
- 提交生成物时，附生成命令。

## 5. 验证（每次改动 / 迁移后）

- 自举重建（**先经用户确认**）；`-Dmcs-only` 加速。
- 示例构建 + `tools/ci.ps1`（构建 / self-test / 8 位仿真 / 预算回归）。
- `mcs251/tools/compiler_sync_check.ps1`：打印 delta 分类，**标出未登记的上游改动**。

## 6. 隐私与许可

- 不拷贝 STC/Keil 专有资料进 fork；路径一律相对/占位；生成物入库前脱敏。
- 第三方许可按仓库 `THIRD-PARTY`。

## 7. 上游 1.0 迁移红线

- **只补插桩，不改上游实现逻辑**；冲突时按「意图」重放，不整段覆盖上游新代码。
- 迁移步骤、冲突处理、验证清单见 [`26-上游跟进方案.md`](26-上游跟进方案.md) §2/§5。
