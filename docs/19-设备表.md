# 19 设备表（芯片契约）规范与用法

> 设备表是**链接布局 / 启动 / SFR 的唯一真源**：构建不再硬编码 `--code-loc/--data-loc/--xram-loc`，
> 编译器按表自动放置变量，SFR 地址由表生成。位置：`devices/stc/`。工具：`tools/mcs_device.py`、
> `tools/mcs_sfr.py`。

## 1. 目录

```
devices/stc/
  model_matrix.toml      型号矩阵（176 型号；--expand 生成 gen/*.toml）
  families.toml          家族→模板映射
  <template>.toml        手写模板（结构 + 典型值），如 ai8051u-34k64.toml、stc32g12k128.toml
  gen/<model>.toml       生成物：`template = "../<模板>.toml"` + [override]（flash/edata/xdata/eeprom…）
  器件矩阵.md            人读总览
  headers.toml           头文件映射
```

## 2. TOML 结构（模板）

- `[device]`：id / vendor / family / model / doc（手册名）/ `sfr_source`（Keil 头，供 `mcs_sfr.py`）。
- `[code]`：`base`（`--code-loc`）、`size`、`addr_width`（16/24）、`movc`、`reset_vector`、`wait_states`。
- `[[memory]]` × N：`kind`（data/idata/edata/xdata/xfr/eeprom）、`base`、`size`、`addressing`
  （direct / indirect_r0 / movx_dptr / movx_dpx）、`bit_addressable`、`alias_of`、`mode`（xfr）。
- `[stack]`：栈所在空间与顶。
- `[link]`：`data_loc` / `idata_loc`。
- `[dptr]`：数量、扩展（DPXL）。
- `[registers]` / `[register_bits]`：少数关键 SFR/位（校验用）。
- `[interrupts]`：`vector_base`、`slot_bytes`、`formula`、`max_number`、`priority_levels`、`numbering`。
- `[override]`（仅 `gen/*.toml`）：按型号覆盖 `flash/idata/edata/xdata/eeprom`。

## 3. 工具：`tools/mcs_device.py`

```powershell
python tools\mcs_device.py <设备.toml> --emit summary         # 人读摘要
python tools\mcs_device.py <设备.toml> --emit sdcc-args        # --code-loc/--code-size/--xram-… 链接参数
python tools\mcs_device.py <设备.toml> --emit lk               # 生成 .lk（含 -b HOME = …）
python tools\mcs_device.py <设备.toml> --emit crt0             # crt0 骨架（HOME 区）
python tools\mcs_device.py <设备.toml> --emit compiler-json    # 内联 JSON（→ MCS_DEVICE）
python tools\mcs_device.py <设备.toml> --emit validate         # 校验
python tools\mcs_device.py --expand devices/stc/model_matrix.toml --out-dir devices/stc/gen
python tools\mcs_device.py --self-test
```

**单段链接上限**：若 `[code].base + flash` 越出地址空间顶部，工具会把 `code.size`/`eeprom.size`
钳到可用空间（例如 STC32G128K：base `FF:0000` → 顶部 64K）；超出部分需拆分链接（见 §5）。

## 4. 与编译器 / 构建对接

- **链接布局**：`xmake f --device=<gen/…toml>`（默认 `devices/stc/ai8051u-34k64.toml`）；
  `xmake/helpers.lua` 的 `device_sdcc_args`/`device_emit` 消费 `--emit sdcc-args|lk|crt0`。
- **变量自动放置**：构建把 `mcs_device.py --emit compiler-json` 结果塞进环境变量 `MCS_DEVICE`；
  后端 `compiler/src/codegen/mcs/device.zig` 据此决定全局放置（显式 `linksection` 优先，否则
  ≤2B→data、其余→设备默认 xdata）。未设 `MCS_DEVICE` 时保持旧行为。
- **SFR**：`tools/mcs_sfr.py --device <设备.toml> --emit zig` 生成 `build/devices/device_sfr.zig`：
  - `dev.sfr.NAME`：地址常量（`u16`）；
  - `dev.reg.NAME`：**寄存器对象**（`anl/orl/write/read/set/clr/cpl`，写 `dev.reg.P1M1.anl(~0x02)`）；
  - `dev.p.NAME`：**C 风格固定地址指针**（`dev.p.P1M1.* &= ~0x02;`，配 `mcs_opt` R6 融单条）；
  - `dev.xfr` / `dev.bit` / `dev.mask`：XFR 地址 / 位地址 / 位掩码。
  **同一 `.zig` 里不要用两套命名空间引用同一寄存器**（后端按短名发 `_<name>`，会撞名）。

## 5. 各内核注意事项

| 内核 | 复位入口/向量 | 代码基址 | 备注 |
| --- | --- | --- | --- |
| AI8051U（251） | `FF:0000` | `0xff0000`，size `0x10000` | 程序存储器 FF:0000–FFFF |
| **STC32G12K128（251）** | **`FF:0000`** | `0xff0000`，size 顶部 `0x10000` | Flash 逻辑地址 **FE:0000–FF:FFFF（128K）**（手册 11.1）；单段只覆盖顶部 64K，`FE:0000` 下半 64K 需拆分链接（**未来**） |
| STC8/STC15/STC89（8 位） | `0x0000` | `0x0000`，size=flash | 传统 8051 单段 |

> **全局变量放置 vs C 互操作（2026-09-19 修）**：C 侧 `--model-large` 的 `extern` 全局在 **xdata**，
> 故 **8 位（mcs51）Zig 定义的 `export var` 一律 xdata**（`device.decide` 对 mcs51 不再自动放 data，
> 否则 C/Zig 各按不同存储访问 → simtest `failcode=0x41`）。251 仍按设备表自动放置（≤2B→data）；
> **与 C 共享的全局**建议在 251 侧显式 `linksection(".xdata")`，避免自动落到 data 后与 C 失配。

> STC32G 结论（2026-09-19，手册 11.1 核实）：**复位入口/向量在 FF:0000**；代码基址必须是
> `0xFF0000`（旧的 `0x000000` 是错的，已修）。128K 全量使用受限于工具链，暂用顶部 64K。

## 6. 新增芯片

1. 在 `model_matrix.toml` 加型号（或直接用现有模板），`--expand` 生成 `gen/*.toml`；
2. 必要时写/改模板（`[code]`/`[[memory]]`/`[interrupts]`），跑 `--emit validate`；
3. `mcs_sfr.py --device <toml> --emit stat/check` 确认 SFR 头可解析、与 `[registers]` 一致；
4. `xmake f --device=<toml>` → `xmake build devhdr` 生成头/`.lk`/crt0，再编示例；
5. `mcs_device.py --self-test`。
