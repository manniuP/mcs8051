# 24 优化器管线总览（构建层后处理）

> 目的：把「Zig 后端 `.asm` → `sdas` 汇编」之间的**构建层优化**理清楚——有哪几道、按什么
> 顺序跑、各守什么安全不变式、加新规则该放哪。各工具的细节见 [15](15-汇编瘦身工具mcs_opt.md)（`mcs_opt`）、
> [16](16-死代码回收mcs_dce.md)（`mcs_dce`）、[17](17-后端IR提示与中间层优化.md)（`mcs_ir`）、
> [22](22-循环下行计数DJNZ.md)（`mcs_loop`）。

## 1. 为什么要有构建层优化

MCS 后端（`compiler/src/codegen/mcs/`）每个内联调用点各出一份代码，且倾向「先把值写进 SPX
帧槽再读回」；`inc/dec spx` 只能步长 1/2/4，prologue/epilogue 会摊成长串；`sdld` 又不回收未用段，
代码很容易顶满 Flash。重编 `zig.exe` 慢，故把「瘦身」做成**文本级后处理**，可独立调试、无需重编。

## 2. 管线顺序（入口：`xmake/helpers.lua: postprocess_asm`）

```
Zig 源 --(zig build-obj -ODebug)--> x.asm
   │
   ├─ fix_mcs_labels.py   修局部标签重名（后端每函数从 L0 重编，同文件多分支会撞名）
   ├─ mcs_opt.py          R1–R6 局部窥孔（**base** 到此处为止）
   │      └─ MCS_KEEP_BASE=1 时另存 x.asm.base（供 mcs_regress E2 差分）
   ├─ mcs_ir.py           消费 `; vN` IR 提示：死 store/死寄存器/死帧槽消除，删提示
   ├─ mcs_loop.py         计数 while → 下行计数 + DJNZ（MCS_LOOP=1 才启用）
   └─ mcs_overlay.py      MCS-51 静态帧叠加（mcs251 @spx 帧是空操作）
   │
   └─ sdas{251,8051} --> .rel
```

另有两条**不在**此管线内、单独跑的：

- `mcs_dce.py`：跨模块可达性，删未引用的全局符号块（`.rel` 前，见 [16](16-死代码回收mcs_dce.md)）。
- `mcs_regress.py`：**回归护栏**，不是优化器（见 §4）。

## 3. 各道职责与安全模型

| 工具 | 层次 | 做什么 | 安全边界 |
| --- | --- | --- | --- |
| `fix_mcs_labels` | 文本 | 按函数给 `Lxx` 加前缀去重 | 只改标签名 |
| `mcs_opt` R1–R6 | 基本块 | 合并 `inc/dec spx`、删冗余 `mov`、`mov` 合并/常量转发、删无用跳转/死代码、**C 风格固定地址 RMW 融合** | 只在基本块内、不跨标签/分支/调用；未知指令当屏障；每条规则带**可证明**前提 |
| `mcs_ir` | 直线块 + 全函数 | 值级死 store（帧槽/寄存器）、删 IR 提示 | 含 `push/pop`/`spx` 调整的函数**整体跳过**（文本偏移失真，曾致 `ziglog` 真机 0 字节） |
| `mcs_loop` | 固定形状 | 常量上界计数循环 → `djnz` | 仅形状完全匹配；带中断的程序注意计数器寄存器 |
| `mcs_overlay` | 函数 | MCS-51 `_frkN` 静态帧叠加 | 对 mcs251 空操作 |
| `mcs_dce` | 跨模块 | 删不可达全局符号 | 以 `--keep`（main/IVT/crt0）为根 |

## 4. 关键不变式：base → final **只删行**（E2 回归）

`mcs_regress.py` 的 E2 断言：最终 `.asm` 必须是 `base`（`fix + mcs_opt`）的**子序列**——即
`mcs_ir` 及之后**只能删整行，不能新增/改写/重排**。理由：历史上出现过「按 asm 文本假设帧布局」
的严重 bug（帧槽相对 SPX，`push/pop` 位移致 `ziglog` 真机 0 字节），这条护栏保证 IR 级优化
只能删除、可逐行归因（`slot`/`block`/`reg`）。

> **推论**：任何**会改写/新增**的优化（如 R6 的「3 行合 1 行」）都必须放在 `mcs_opt` 里，
> 即**属于 base**；放 `mcs_ir` 之后会破坏子序列不变式。

## 5. R6：C 风格固定地址 RMW 融合（2026-09-19）

背景：`dev.p.P_SW1.* &= ~0xc0;`（C 风格固定地址指针）经后端先摊成
`mov a,0xba ; mov @spx,a ; anl a,#0x3f ; mov @spx-0x1,a ; mov 0xba,a`，比 `mcs.sfrAnd` 的
单条 `anl 0xba,#0x3f` 多出读-改-写与帧溢出。

R6 在 `mcs_opt` 内把该模式融为单条 `anl/orl/xrl dir8,#imm`；`mov a,#C ; mov dir8,a` 则由
**R4 扩展到直接地址** → `mov dir8,#C`。安全性：

- 末尾 store 之后 **A 不再被读**（`_a_dead_after`，跳过 `G$…==.`/`C$…==.` 调试符号行）；
- 中间溢出的帧槽此后**不再被读**（`_slots_dead_after`；遇 `push/pop`/`spx` 调整后，再有
  任何 `@spx` 访问即判不安全——收尾 `dec spx; eret` 之后无 `@spx`，可放行）；
- `dir8` 在模式内只被读、不被写。

不满足则原样保留（如 RMW 是函数最后一条、A 即返回值时）。例：`examples/ai8051u/sfr_ptr`
（`xmake build zigsfrptr`）产出 `orl 0x92,#0x02` / `anl 0x91,#0xfd` 单条。

## 6. 加新规则该放哪

- **会删/改指令** → 放 `mcs_opt`（属 base，E2 不受影响）。优先复用其值编号 `Stream` 与
  `_a_dead_after`；无法证明就放弃（宁可少优化）。
- **只删整行** → 可放 `mcs_ir`（但注意 `push/pop` 跳过、子序列约束、逐行归因）。
- 规则都要有 **`--self-test` 用例**（正例 + 不触发反例），并让 `mcs_opt` 规则可 `--no-rN` 关闭；
  改完跑 `mcs_opt/mcs_ir/mcs_regress --self-test` 与各示例构建。

## 7. 根治方向（后端）

文本级优化是过渡手段。根治仍是后端**寄存器分配**与**固定地址直址 RMW**（在 `CodeGen.zig`
里对「固定 direct 地址的 `x op= imm`」直接发 `anl/orl dir8,#imm`），可省去帧溢出与后处理。
需重编编译器（自举须先经用户确认），见 [docs/交接 §5.10③]。
