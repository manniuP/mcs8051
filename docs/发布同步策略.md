# 发布同步策略（单仓，2026-09-19 起）

> **2026-09-19：`mcs251` 与 `mcs8051` 已合并为同一仓库/同一历史。** `mcs251` 是本地工作树，
> `origin = git@github.com:manniuP/mcs8051.git`（公开）。不再需要「按内容同步」——发布就是正常的
> `git push origin main`。旧的双仓同步流程作废（历史见本文件 git log）。

## 角色（合并后）

| 位置 | 角色 | 远程 |
| --- | --- | --- |
| `mcs251`（本地） | **开发工作树** | `origin` → `manniuP/mcs8051`（分支 `main`） |
| `manniuP/mcs8051` | **公开仓** | 由 `mcs251` push |

- `compiler` 子模块 → `manniuP/zig-mcs51-backend`（分支 `mcs251-backend`）。
- **`sdcc` 不是子模块**：C 构建用预编译工具链（`tools/sdcc-mcs251-windows-x64`）；SDCC 源码镜像在
  工作区 `sdcc-c251/`。（合并前 `mcs251` 曾把 `sdcc` 作子模块，合并时按「公开仓内容为准」移除。）
- 历史：`main` 含两条根（mcs8051 发布历史 + mcs251 开发历史），由 merge commit `2e67b4e2` 连接；
  **内容以公开仓为准**。

## 发布流程

1. 在 `mcs251` 改、提交（commit 分层见 [`27-上游迁移协定.md`](27-上游迁移协定.md)）。
2. **后端源码有变**：先 push fork —— `cd compiler && git push origin mcs251-backend`，
   并更新 `versions.toml` 的 `[compiler] commit`。
3. `git push origin main`（`mcs251` → `mcs8051`）。
4. 打 tag `v*` → 触发便携工具链 CI，产物进 Release。
