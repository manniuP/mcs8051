# 发布同步策略：`mcs251` ↔ `mcs8051`

> 记录时间：2026-09-17。适用于 `manniuP/mcs8051`（发布）与本地 `mcs251`（开发）。

## 角色

| 仓 | 角色 | `compiler` | `sdcc` |
| --- | --- | --- | --- |
| 本地 `mcs251` | **开发源** | 子模块 → `manniuP/zig-mcs51-backend`（2026-09-19 起） | 子模块 → `manniuP/sdcc-c251` |
| `manniuP/mcs8051` | **发布 / 门面仓** | 子模块 → `manniuP/zig-mcs51-backend` | 子模块 → `manniuP/sdcc-c251` |

两者**非 `compiler`/`sdcc` 的项目内容应保持一致**；以下文件**各仓专用、允许不同**：
`README.md`（各自定位）。`mcs251` 与 `mcs8051` 现在都是 `compiler`+`sdcc` 两个子模块
（`mcs251/compiler` 曾是内联目录，2026-09-19 迁移为子模块，见 `docs/26-上游跟进方案.md`）。
线尾（LF/CRLF）差异忽略。

## 发布流程（`mcs251` → `mcs8051`）

1. **后端源码有变**（`mcs251/compiler/`）：先提交并 push 到
   `manniuP/zig-mcs51-backend`（`mcs251-backend` 分支），记下新 commit。
2. 把 `mcs251` 的非 `compiler` 内容同步到 `mcs8051`（**不要**覆盖 `mcs8051` 的
   `README.md` / `.gitmodules`）。
3. 更新 `mcs8051` 的 `compiler` / `sdcc` 子模块指针 + `versions.toml` 记录。
4. `commit` + `push`；打 tag `v*` → 触发便携工具链 CI，产物进 Release。

## 回灌（`mcs8051` → `mcs251`）

若直接在 `mcs8051` 上改了通用文件（如 CP1252 修复），**必须回灌** `mcs251`，
否则下次发布会被旧版本覆盖。已知回灌（2026-09-17，commit `07c91baac3`）：
`tools/mcstools.py`（stdout/stderr 强制 UTF-8）、`tools/build_mcstools.ps1`（`ErrorActionPreference`）、
`build/examples/ai8051u/zig_{t0print,uart_echo}/crt0_mcs51.asm` + `.gitignore` 例外。

## 核对命令

```bash
# mcs251（开发源）HEAD 与 mcs8051（发布）HEAD 的非 compiler/sdcc blob 对比
a=<workspace>/mcs251 ; b=<mcs8051 克隆>
git -C "$a" ls-tree -r HEAD | grep -vE '(^|\t)(compiler/|sdcc)' > /tmp/a
git -C "$b" ls-tree -r HEAD | grep -vE '(^|\t)(compiler|sdcc)' > /tmp/b
diff <(awk '{print $3, $4}' /tmp/a | sort) <(awk '{print $3, $4}' /tmp/b | sort)
```
